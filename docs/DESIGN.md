# Design

当前设计依据位于 `design-docs/versions/mvp/`。本文件是闲遇 MVP 的设计系统短入口，用于把原型中的视觉语言转成后续工程实现可执行的规则。

## 当前工件

- UI 原型：`design-docs/versions/mvp/prototype.html`
- 设计说明：`design-docs/versions/mvp/notes.md`
- 原型规则：`checks/prototype-checklist.md`

产品范围以 `product-specs/versions/mvp/` 为准。设计稿不得引入 MVP 剔除项：线上支付、微信授权手机号、文件上传、会员自助购卡、员工自助注册。

## 设计原则

- 业务优先：闲遇是高密度门店运营工具，不做营销落地页式的装饰堆叠。
- 信任优先：会员绑定、核销、冻结、发卡和报表必须让用户知道发生了什么、为什么、下一步做什么。
- 通用优先：文案和组件不得把产品限定为单一行业，统一使用服务项目、员工、资源、会员卡、预约时段等通用概念。
- 状态优先：空态、加载、失败、成功、禁用、冻结和阻断都必须有可见状态，不允许只靠 toast 或只靠颜色表达。
- 扫读优先：核心页面首屏只服务一个主任务，最多展示三个次任务，其余内容进入下方区域或详情页。

## 设计 Token

店长、教练和会员小程序共享健康可信的绿色业务工具体系；平台后台使用独立的“企业经纬”企业运营体系。两套 token 服务不同端面，不交叉套用。

### 字体与排版

- MVP 实现优先使用系统中文字体栈：`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`Noto Sans SC`、`PingFang SC`、`Microsoft YaHei`、`sans-serif`。这是小程序可用性选择，不作为品牌长期字体结论。
- 小程序正文最小 16px；辅助说明最小 12px；按钮文字最小 13px。
- 后台正文最小 14px，表格主要内容不小于 14px，表头不小于 12px。
- 标题行高控制在 1.15 到 1.3；正文和说明行高控制在 1.5 到 1.75。
- 金额、次数、预约数、核销数等数字列必须使用等宽数字或等价的数字对齐方案。
- 不使用负字距；中文正文不做大段居中排版。

### 间距与圆角

- 间距采用 4px 基础步进，常用值为 4、8、12、16、20、24、32。
- 小程序页面横向安全边距默认 18px 到 20px。
- 小程序业务卡片圆角以 8px 为主；手机外框、演示画板和品牌标识可以使用更大圆角。
- 平台后台表格、表单和业务面板圆角以 3-5px 为主；阴影只用于抽屉层级，不用于普通页面区块。
- 卡片内部信息组之间用 8px 到 12px，跨区域分组用 18px 到 24px。
- 抽屉底部操作区随内容滚动出现在表单底部，不固定悬浮，避免遮挡小屏输入内容。

## 组件规则

| 组件 | 默认规则 | 必备状态 |
| --- | --- | --- |
| 主按钮 | 小程序使用松绿色，平台后台使用商务蓝；承载本页唯一主操作，触控高度不小于 44px。 | 默认、按下、loading、禁用、失败后可重试。 |
| 次按钮 | 白底或浅底，弱于主按钮，用于返回、取消、保留预约。 | 默认、按下、禁用。 |
| 风险按钮 | 用珊瑚橙，仅用于冻结、取消、删除、阻断确认。 | 默认、确认中、禁用。 |
| 状态标签 | 使用颜色 + 文案，不单独作为操作按钮。 | 正常、信息、预警、风险、禁用。 |
| 表单字段 | 必须有可见 label，必填项用红色“必填”标记。 | 默认、聚焦、已填、字段错误、禁用、只读。 |
| 列表行 | 左侧身份或序号，中间主信息，右侧状态或明确操作。 | 默认、选中、不可选、处理中。 |
| 抽屉 | 保留底层页面语义，标题说明当前动作；支持关闭按钮、点击非抽屉区域和 Esc 关闭，底部操作随内容滚动。 | 打开、提交中、失败保留输入、成功关闭。 |
| 空态 | 业务流程空态说明为什么为空并给出后续路径；平台后台数据表可使用紧凑空态。 | 首次空、筛选无结果、权限不可用、冻结只读。 |
| 表格 | 后台表格必须保留表头、状态、行操作按钮组和分页。 | 加载、空、筛选无结果、错误、分页。 |

## 核心页面首屏优先级

| 页面 | 首屏主任务 | 最多三个次任务 | 后移内容 |
| --- | --- | --- | --- |
| O-START | 完成三项必填并创建门店 | 门店资料、营业时间、履约资源 | 创建后由工作台承接的运营配置。 |
| O-DASHBOARD 创建后待办 | 推进开放预约前下一步 | 创建员工、设置服务、创建会员卡 | 经营摘要和报表入口。 |
| O-DASHBOARD 运营态 | 今天先处理什么 | 到店/核销、低余额、临期会员 | 趋势、完整报表、长期配置。 |
| O-REPORT | 看清销售额、预约、到店、核销 | 售卡明细、预约到店、会员卡提醒 | 员工维度、服务表现深层分析。 |
| O-SCHEDULE-HOME | 找到需要发布或补齐的时段 | 日期筛选、复制、预检异常 | 历史排期分析。 |
| O-MEMBER-HOME | 添加会员或处理待绑定/预警会员 | 待绑定、余额不足、即将到期 | 全量会员运营分析。 |

## 空态结构

所有核心空态必须包含五件事：

1. 当前为什么为空。
2. 系统已经知道什么。
3. 推荐主操作。
4. 替代路径。
5. 用户做完后会看到什么变化。

示例：

- 无员工：说明“还没有可履约员工”，主操作“新增员工账号”，替代路径“先保存服务草稿”，完成后“服务可绑定员工并进入排期”。
- 无服务：说明“还没有可预约服务项目”，主操作“创建服务项目”，替代路径“先检查资源和员工”，完成后“会员卡和排期可选择该服务”。
- 无可用卡：说明“当前没有适用、未过期且余额足够的会员卡”，主操作“联系门店”，替代路径“返回服务列表”，不得出现购买或支付入口。
- 报表无数据：说明“当前范围内暂无线下售卡、预约或核销记录”，主操作“切换月份/全部历史”，替代路径“去添加会员并发卡”。

平台后台租户列表属于查询型数据表：无结果时仅在表格内容区显示“暂无数据”，不追加说明卡片或“查看全部租户”按钮；总数为 0 时隐藏分页。该例外不改变业务流程型空态的五项结构。

## 表单反馈规范

保存、发布、创建、发卡、预约、核销、取消、解冻类操作必须覆盖以下状态：

| 状态 | 用户看到什么 | 实现规则 |
| --- | --- | --- |
| loading | 主按钮进入“提交中/保存中/发布中”，重复提交禁用。 | 保留页面内容，不清空表单。 |
| success | 明确成功文案，并返回来源页、刷新列表或进入结果页。 | 成功反馈不能只靠颜色。 |
| field_error | 错误出现在字段旁，并在表单顶部展示错误摘要。 | 保留输入，焦点回到第一个错误字段。 |
| form_error | 说明失败原因和下一步，例如重试、联系门店、返回列表。 | 不得吞掉后端错误。 |
| partial | 部分保存成功时说明哪些已保存、哪些待处理。 | 首次开店草稿和批量配置必须支持。 |
| disabled | 说明为什么不能点，例如缺员工、无适用会员卡、冻结。 | 禁用态仍要可读。 |

## 响应式与可访问性

- 小程序实现必须验证 320、375、390、430 四个宽度；390px 画板只是基准，不是唯一可用尺寸。
- 后台实现必须验证 1280、1440 和宽表格场景；低于 1280 时优先保持表格横向滚动和关键列固定，不把后台硬塞成小程序式卡片。
- 平台后台侧栏、顶部栏和主内容使用统一栅格；表单页沿主内容起始线左对齐，不因字段较少改成居中展示。
- 长门店名、长员工名、长地址、长服务范围必须换行或截断，并保留可查看完整内容的方式。
- 触控目标不小于 44px；并排按钮间距不小于 8px。
- 键盘可操作元素必须有可见焦点态；后台表格行操作、筛选和弹窗必须能按键盘顺序到达。
- 平台后台输入框、下拉选择、日期选择和文本域聚焦时只使用单层商务蓝边框，不叠加外侧 `outline` 或光环。
- 表单错误必须能被屏幕阅读器关联到对应字段；页面级错误摘要应出现在表单标题下方。
- 动效必须尊重减少动态效果设置；状态变化优先靠布局、文案和颜色，不依赖动画。
