# Frontend

当前仓库包含店长、员工、会员三个 Taro 小程序端和 Vue 3 平台后台的可运行应用代码。本文件是前端实现短入口，产品与视觉依据为 active MVP 规格和当前 UI 原型。

## 当前依据

- 产品规格：`product-specs/versions/mvp/spec.md`
- 原型说明：`product-specs/versions/mvp/prototype-notes.md`
- UI 原型：`design-docs/versions/mvp/prototype.html`
- 工程入口：`architecture/index.md`

前端实现应覆盖店长、员工、会员小程序和平台后台四类端面，并遵循 `checks/prototype-checklist.md` 的可用性规则。

## 响应式基准

### 小程序端

小程序端以 390px 画板为视觉基准，但不能按固定画板宽度硬编码页面。店长、员工、会员三个小程序端必须支持不同机型页面自适应，至少覆盖以下宽度：

| 宽度 | 验证重点 |
| --- | --- |
| 320px | 长门店名、长服务标签、底部导航、双按钮、抽屉表单不得横向溢出。 |
| 375px | iPhone 常见宽度，首屏主任务和主按钮必须可见。 |
| 390px | 与当前原型对齐。 |
| 430px | 大屏手机不应出现松散空洞，列表和卡片保持密度。 |

小程序页面规则：

- 页面根容器使用相对宽度和安全区适配，不使用固定 390px 宽度。
- 顶部栏、底部导航、抽屉底部操作必须适配刘海屏、圆角屏和底部安全区。
- 底部导航固定为当前端的主要导航，不在工作台重复相同入口文案。
- 店长端底部导航固定为工作台、排期、会员、报表、我的；员工端固定为今日、名单、核销、记录、我的；会员端固定为首页、预约、卡包、记录、我的。
- 抽屉和表单底部操作随内容滚动出现，不固定遮挡输入项。
- 长文本优先换行；状态标签和右侧操作拥挤时，状态换到第二行，主操作保持可点。
- 不允许出现横向滚动。
- 系统字体放大时，主操作按钮仍需可见且可读。
- 列表、卡片、表单和按钮组在小屏上优先纵向堆叠，在大屏手机上保持业务密度，不因拉伸产生大面积空白。

### 平台后台

后台端以桌面管理系统为准，不要求提供手机端后台，但必须支持不同桌面和笔记本屏幕大小页面自适应，至少覆盖：

| 宽度 | 验证重点 |
| --- | --- |
| 1024px | 笔记本窄屏下侧栏、搜索、筛选和主要操作仍可访问；必要时收紧间距或折叠次要筛选。 |
| 1280px | 侧栏、表格、筛选区和行操作按钮组保持可用。 |
| 1440px | 当前桌面原型主要对齐宽度。 |
| 1920px | 内容区不无限拉宽，表格和详情页保持可扫读行长。 |
| 宽表格 | 租户列表、配置列表、操作记录必须允许横向滚动或关键列固定。 |

后台页面规则：

- 后台使用深海军蓝侧栏、冷灰白工作区、商务蓝主操作、3-5px 容器圆角和紧凑表格；不套用小程序绿色主题。
- 登录页使用左右分区但不放装饰边角线，表单不包裹在卡片中；登录后页面不显示研发说明、内部标签或英文编号式面包屑。
- 客服微信配置使用与其他页面相同起始线的单一全宽表单，不居中收窄，不展示冻结页预览或三端展示规则。
- 后台不改造成移动端卡片流；窄屏时优先保障搜索、筛选、状态和行操作。
- 主内容区应设置合理最大宽度或表格容器宽度，不因超宽屏拉伸到难以扫读。
- 侧栏在窄屏下可收窄为图标栏或保持固定最小宽度，但不得遮挡表格和弹窗。
- 筛选区在窄屏下允许换行或折叠次要筛选，主搜索和状态筛选必须保留在首屏。
- 表格行操作必须是按钮组，不使用纯文字操作。
- 状态列同时使用颜色和文字；到期、冻结、延长等状态不得只靠颜色。
- 分页、筛选、搜索状态应可被 URL 或页面状态恢复，避免刷新后丢失上下文。

## 长文本和极端数据

必须用以下极端数据检查页面：

- 门店名：20 个以上中文字符。
- 地址：40 个以上中文字符。
- 员工名：中英文混合，最长 20 字符。
- 服务名：20 个以上中文字符。
- 服务标签：10 个标签，单个 8 个字。
- 会员卡名：20 个以上中文字符。
- 金额：`¥0.00`、`¥999999.99`。
- 时间：跨午晚高峰，如 `09:00-21:30`。

处理规则：

- 标题可两行，超过两行应截断并提供完整信息入口。
- 标签可换行，不压缩到不可读。
- 表格单元格可截断，但鼠标悬停或详情页必须能看到完整内容。
- 数字列右对齐或等宽数字显示。

## 表单和反馈实现

所有保存、发布、发卡、预约、核销、取消、解冻类操作必须实现以下状态：

- `idle`：可编辑，主按钮可点击。
- `loading`：主按钮显示提交中，重复提交禁用。
- `success`：明确成功文案，并刷新来源页或进入结果页。
- `field_error`：错误显示在字段旁，顶部显示错误摘要。
- `form_error`：保留输入，说明失败原因和下一步。
- `partial`：部分成功时说明已保存项和待处理项。
- `disabled`：说明禁用原因，例如缺员工、无适用会员卡、租户冻结。

错误展示优先级：

1. 字段旁错误。
2. 表单顶部错误摘要。
3. 页面级阻断提示。
4. toast 只作为补充，不作为唯一反馈。

## 关键交互闭环

- 店长端资源删除必须进入二次确认；有关联未来排期、服务项目占用，或删除后启用资源少于 1 个时，确认按钮禁用并展示阻断原因。
- 店长端排期保存草稿和发布成功后必须刷新排期首页对应日期，并高亮新保存或新发布的时段。
- 店长端报表明细只在同一页面内通过标签、筛选和列表切换维度；MVP 不新增独立会员、会员卡、服务或员工详情页。
- 会员端我的预约必须有预约详情；详情承接待服务、候补、已完成和已取消状态，并决定是否允许取消。
- 会员端超过取消截止或租户冻结时必须进入取消阻断态，确认取消按钮禁用，不释放名额、不变更预约状态。
- 平台后台冻结租户必须二次确认，原因和确认勾选缺失时禁用提交；成功后刷新租户详情和操作记录。
- 平台后台租户详情、租户调整和平台配置修改使用右侧抽屉；所有抽屉均支持点击非抽屉区域或按 Esc 关闭。抽屉打开后焦点进入抽屉，关闭后回到触发按钮，保存成功后刷新来源列表当前行。
- 四端操作反馈统一覆盖 loading、成功、失败、字段错误、页面级阻断、禁用原因和重复提交禁用。

## 可访问性实现

- 所有可点击元素触控区域不小于 44px。
- 后台端所有按钮、筛选、分页、右侧抽屉和行操作必须支持键盘访问。
- 键盘焦点态必须可见，不允许移除 outline 后没有替代样式。
- 表单 label 必须可见；不得只用 placeholder 当 label。
- 字段错误必须和字段建立语义关联。
- 弹窗和抽屉打开后，焦点进入弹层；关闭后回到触发元素。
- 状态不得只靠颜色表达，必须有文字或图标说明。
- 动效必须尊重 `prefers-reduced-motion` 或小程序等价设置。

## 空态实现

核心空态不得只写“暂无数据”。每个空态必须包含：

1. 为什么为空。
2. 系统已经知道什么。
3. 下一步主操作。
4. 可选替代路径。
5. 完成后用户会看到什么变化。

必须覆盖的空态：

- 店长端：无员工、无服务、无会员、无会员卡、无排期、报表无数据。
- 员工端：今日无服务、账号停用或门店冻结。
- 会员端：未绑定、无可用卡、无预约记录、冻结只读。
- 后台端：租户列表无结果、操作记录无结果、配置搜索无结果。

## MVP 剔除项守卫

前端不得新增以下入口或文案：

- 微信授权手机号。
- 线上支付、购买、订单、退款、发票、分账。
- 上传头像、图片、二维码、附件、资质。
- 会员自助购卡、在线充值、在线续费。
- 员工自助注册。

如果界面需要头像或二维码位置，只能使用系统生成文字占位或静态样式，不出现上传入口。
