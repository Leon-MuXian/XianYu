# 闲遇 MVP 工程映射

文档日期：2026-06-07  
状态：active architecture  
适用版本：`seren-meet` / `mvp`

本目录是 MVP 的最终工程设计入口，不保留过程评审、阶段计划或临时迭代文档。工程实现以完整 MVP 为目标，开发优先级不改变系统边界、数据模型和接口设计。

## 读取顺序

1. `tech-stack.md`：技术栈、可落地性和扩展性。
2. `development-blueprint.md`：仓库结构、代码规范、本地命令和工程骨架目录。
3. `system-design.md`：系统边界、模块划分、四端页面到工程模块映射。
4. `data-model.md`：全局数据库设计和核心约束。
5. `api-map.md`：店长端、教练端、会员端、平台后台四端完整 API。
6. `deployment.md`：最终部署拓扑、环境、发布和运维边界。
7. `implementation-status.md`：正式范围与当前代码状态矩阵。
8. `prototype-implementation-map.json`：74 个原型画板/状态的机器可读实现映射。

## 设计原则

- 不把课程、教练、教室写死为行业模型；底层统一使用服务项目、员工、资源、可预约时段。
- 后端 API 默认租户隔离，平台后台只通过受控后台接口跨租户查看和操作。
- 会员卡是门店线下售卖并在系统内发放的权益，不是平台支付商品。
- 报表是经营记录聚合，不是财务结算系统。
- 租户冻结不删除数据，只限制业务写操作和履约操作。
- 保持 MVP 剔除项：不做线上支付、不接入微信授权手机号、不做文件上传、不做会员自助购卡、不做员工自助注册。

若工程文档与产品规格冲突，以 `../../../product-specs/versions/mvp/` 和 `../../../design-docs/versions/mvp/prototype.html` 为准，并同步更新工程映射。
