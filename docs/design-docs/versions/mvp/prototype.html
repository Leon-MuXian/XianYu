这版 MVP 设计稿按当前版本文档输出。视觉上采用高密度小程序画板、业务卡片、状态标签、底部导航、登录插画和后台表格；业务上呈现 MVP 的通用模型：门店先配置资源和员工，再创建服务项目、会员卡售价、会员权益与可预约时段，会员用可用卡预约，员工到店确认并核销，店长查看销售、预约、核销和预警报表。

MVP 链路地图

每条链路由 MVP 页面契约直接生成，页面 ID 与业务实体一一对应。当前原型保留完整 MVP 链路，同时前置试点楔子：发卡、到店、核销、余额变化、低余额和到期预警。

试点楔子

店长先录入会员和会员卡，员工确认到店后完成核销，店长用报表处理低余额和到期预警。

O-MEMBER→S-ATTEND→S-DEDUCT→O-REPORT
验收重点第一阶段优先验证会员权益台账、员工核销和预警处理，预约作为完整 MVP 后续能力。

店长启用

登录后确认 30 天免费试用，在开始使用页完成门店资料、营业时间和履约资源，创建门店后进入工作台继续补齐待办。

O-LOGIN→O-START→O-STORE/O-HOURS/O-RESOURCE→O-DASHBOARD
验收重点创建门店按钮默认禁用，三个必填项完成后才可创建；字段不绑定单一行业。

完整预约

会员输入邀请码后先查询门店信息，核对门店和会员卡无误后确认绑定，再选择适用卡预约。

M-BIND→M-BIND-CHECK→M-CARDS→M-CONFIRM
验收重点查询门店不直接绑定；无可用卡时只联系门店；候补只记录意向，排在试点楔子之后实现。

平台续期

报表汇总线下售卡、到店、核销和预警；试用到期后后台人工查看试点数据并解冻。

O-REPORT→O-FROZEN→A-TENANTS→调整抽屉
验收重点后台能观察发卡、核销、预警和续期状态；销售额来自线下售卡记录。

店长小程序

店长端按注册试用、创建门店前、创建后配置、日常运营、账号设置和冻结异常组织。导航栏保持紧凑，只承担页面定位；状态由原有业务内容表达，列表新增动作进入内容标题行，保存与确认继续跟随表单。
