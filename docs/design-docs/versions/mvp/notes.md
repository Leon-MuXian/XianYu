# 闲遇 MVP Prototype Notes

版本：MVP
文档日期：2026-07-24
当前 UI 设计稿：`prototype.html`

## 原型说明

本目录保存当前唯一 MVP UI 设计稿。阅读、实现或验收 MVP 时，应配合 `docs/product-specs/versions/mvp/` 下的正式版本文档使用。

本原型按 MVP 页面契约输出全部主体画面。店长、教练和会员端采用高密度业务工具风格：390px 小程序画板、8px 卡片、松绿色/深墨色/珊瑚橙/数据蓝/提示金配色、登录插画、业务卡片、状态条和底部导航。平台后台 WEB 端采用“企业经纬”专属视觉层：1440px 桌面画板、深海军蓝导航、冷白数据工作区、克制蓝色主操作、3-5px 圆角、紧凑表格和右侧抽屉；该视觉层不改变业务字段、状态分支或操作约束。业务内容只呈现 MVP 的通用模型。全部端的画板均会标记页面类型：“效果呈现”代表用户实际会看到或操作的页面/状态，“研发说明”代表仅供研发实现时参考的规范说明画板；当前只有 O-FEEDBACK 四端操作反馈规范为研发说明，教练端、会员端和平台后台 WEB 端页面均为效果呈现。

## 试点楔子 UI 重排

当前完整 MVP 原型继续作为页面覆盖基线。根据 `../../../product-specs/versions/mvp/pilot-wedge.md`，第一阶段 UI 应优先验证“会员卡权益台账 + 员工核销 + 低余额 / 到期预警”。后续修改 `prototype.html` 时，应把店长、员工、会员和平台后台的首屏任务重排到权益经营主线，而不是新增一套视觉风格。

重排原则：

- 店长端第一眼看到今天待到店、待核销、低余额、即将到期和本月线下售卡。
- 员工端第一眼看到今天需要确认到店和核销的会员。
- 会员端第一眼确认绑定门店、会员卡余额和最近核销记录。
- 平台后台第一眼看到试点租户是否完成发卡、是否发生核销、是否触发预警和是否通过客服续期。
- 完整排期、会员自助约课、候补、复杂取消和报表下钻仍保留为完整 MVP 能力，但第一阶段不应压过权益台账主线。

- 链路地图：店长启用、会员预约、员工履约、报表预警、试用冻结。
- 店长小程序：微信登录、开始使用新用户告示、开始使用、门店资料、营业时间、资源管理新增资源底部抽屉态、资源管理列表态、资源删除确认/阻断态、工作台创建后待办态、员工列表、员工页内新增员工底部抽屉状态、员工页内修改员工底部抽屉状态、服务项目、服务项目资源员工下拉多选状态、服务无员工阻断态、会员卡管理列表、会员卡新增次数卡页面、会员卡修改期限卡页面、会员卡删除的启用态提示/可删除确认/已发卡阻断态、添加会员并发卡、发卡成功邀请码状态、发布预约时段、排期预检失败态、排期发布成功态、工作台运营态、排期首页、会员首页、报表、报表明细、我的、冻结页和四端操作反馈规范；微信登录页背景从屏幕顶端延伸至状态栏，品牌导航行按微信胶囊位置避让，不使用独立白色状态栏占位；门店资料页使用底部抽屉依次选择城市、区/县并填写详细地址，不展示省/直辖市字段或抽屉内合成地址，门店名称展示唯一性反馈，联系电话不展示格式或唯一性状态，页面不展示说明卡或完整门店预览；开始使用新用户告示展示免费试用权益和当前试用天数，当前默认值为 30 天，由平台配置决定；首次开店流程采用 O-START 清单式引导，门店资料、营业时间和履约资源为必填项，创建门店按钮默认禁用，必填项完成后在 O-START 展示完整门店预览，可点击创建并进入工作台；工作台负责“今天要处理什么、下一步做什么、哪些异常要关注”，创建后待办态展示开放预约前配置进度和下一步待办，运营态展示今日处理、任务化动作、风险提醒和轻量经营摘要，不重复底部导航文案；员工页不展示待完善状态统计，仅员工列表行支持一键复制员工姓名、登录账号和当前登录密码，员工列表页不展示“修改员工账号”和“新增员工”说明卡片，新增员工抽屉和修改员工抽屉均不提供复制账号操作；修改抽屉打开时回显账号与密码，并提供账号资料修改、密码修改、启用/停用和物理删除账号，删除前校验关联项目并在有关联时禁用删除；店长端所有需要店长输入或配置的表单字段使用红色“必填”标记；服务项目按真实创建场景展示基础信息、启用前检查和资源/员工下拉多选，资源与员工均支持多选且停用项不可选；会员卡管理采用经营摘要清单，页面只保留一个新增按钮，新增时先选择次数卡或期限卡并进入现有新增页面，填写页不再展示卡类型切换，点击已有会员卡进入修改页面，不将新增页面改为抽屉，不展示组合卡、“发给会员后怎么用”或“保存前检查”说明块，服务和员工多选超过 2 项时只显示已选数量；修改页常驻展示删除入口，启用模板先停用，停用且未发卡模板二次确认后删除，已发卡模板进入阻断态并保留历史权益；发卡成功页只展示邀请码、绑定提醒、重新生成、实收金额和绑定状态等用户能理解的信息，不暴露后台枚举；排期保存草稿和发布成功后回到排期首页对应日期并高亮新时段；报表首页展示销售额、预约、到店、核销、售卡明细、预约到店、服务表现和会员卡提醒等业务内容，并以店长可理解的分组、文案和趋势图呈现；报表明细下钻只在 O-REPORT-DETAIL 内通过标签、筛选和列表切换维度，不新增独立会员、会员卡、服务或员工详情页；资源管理列表态中启用/停用仅为只读状态标识，资源行提供修改和删除入口，删除资源必须二次确认且在有关联未来排期、服务项目占用或会导致启用资源少于 1 个时禁用确认；店长端底部导航统一为工作台、排期、会员、报表、我的；冻结后店长端强制进入冻结页，除 O-FROZEN 外不允许访问其他业务页面或设置页面。
- `O-LOGIN` 登录页品牌统一显示“闲遇-店长端”，不在右侧重复展示角色；页面作为固定首屏禁用无内容拖动，并通过矮屏布局保证登录按钮与底部说明完整可见。
- `O-STAFF` 员工列表使用页面内部纵向滚动，保留完整滑动能力但不显示滚动条；顶部栏、底部导航和员工抽屉不随列表滚动。
- `O-MEMBER` 添加页只展示会员姓名、必填联系方式、发放会员卡和实收金额；会员编号由后台生成，不展示编号输入、“实收确认”或“保存后生成邀请码”提示卡。
- 教练小程序：独立于会员端展示，账号密码登录沿用既有登录页；覆盖账号状态、完善资料、今日服务、今日无服务空态、预约名单、到店确认成功、核销确认、核销阻断、服务记录、我的和冻结提示。
- 会员小程序：独立于教练端展示，微信登录沿用既有登录页；覆盖邀请码填写、加载门店信息、核对门店并确认绑定、绑定失败、卡包、约课首页、服务详情、确认预约、无可用卡、预约成功、候补成功、我的预约、预约详情、取消预约、取消阻断、服务记录、我的和冻结提示；邀请码绑定以“填写邀请码 → 查询/加载门店信息 → 核对门店与会员卡 → 确认绑定”呈现，查询门店信息不直接完成绑定；预约详情承接待服务、候补、已完成和已取消状态，超过取消截止或租户冻结时进入取消阻断态。
- 平台后台 WEB 端：登录页和登录后的全部页面采用“企业经纬”企业运营工作台。覆盖租户管理列表、租户详情右侧抽屉、租户调整右侧抽屉、客服微信配置、平台配置与右侧抽屉编辑态、操作记录。登录后采用“侧栏导航 + 单一内容头部”，不重复展示顶部面包屑栏，当前模块由侧栏选中状态表达，页面名称与说明由内容区标题表达；侧栏会话区固定显示“平台管理员”角色，账号行绑定当前认证用户的真实 `username`；租户由店长首次微信登录自动开通，后台不提供新建租户入口；租户列表的五项状态概览使用统一底色和层级，不用顶部状态彩线制造独立卡片感，并保留首列固定、客服微信长文本截断、线下售卡商务化金额和左对齐操作按钮；租户详情/调整使用右侧抽屉，冻结状态展示冻结原因和延期并解冻，未冻结状态展示冻结账户操作；客服微信配置使用与其他后台页面相同起始线的单一全宽表单，不居中收窄，不展示冻结页预览和三端展示规则，其中展示文案与展示范围默认使用单行输入高度，内容换行时最多自适应到三行；平台配置使用可编辑下拉筛选、右侧查询按钮和右侧抽屉编辑，页面标题区不重复展示后续生效提示，生效规则由说明文案、影响范围列和编辑抽屉承接；操作记录使用 `YYYY-MM-DD HH:mm:ss` 时间格式。页面保持既定 ID、字段、筛选条件、状态文案、动作、必填规则、保存结果和审计约束。

## 设计系统补充

本原型的正式设计系统入口为 `../../../DESIGN.md`。实现时不得只复制 `prototype.html` 中的局部 CSS，应按 `../../../DESIGN.md` 的 token、组件状态、响应式和可访问性规则统一落地。

必须保持的设计 token：

- 主操作：松绿色 `#2F7D6E`。
- 强主操作：深松绿色 `#195B50`。
- 标题文本：深墨色 `#17211B`。
- 次要文本：灰绿色 `#60706A`。
- 风险/阻断：珊瑚橙 `#E86F4E`。
- 数据信息：数据蓝 `#3F6E9D`。
- 试用/预警：提示金 `#B98532`。
- 背景：浅绿色灰 `#F5F7F2`。
- 卡片和抽屉表面：白色 `#FFFFFF`。
- 卡片圆角：业务卡片以 8px 为主。

平台后台 WEB 端使用“企业经纬”专属 token；上述绿色 token 只用于三个小程序端：

- 导航底色：深海军蓝 `#172433`，导航活动面 `#213246`。
- 主操作：商务蓝 `#285F98`，强调主操作 `#194978`。
- 工作区背景：冷灰白 `#F2F5F8`，数据表面 `#FFFFFF`。
- 标题文本：墨蓝黑 `#172233`，次要文本 `#637286`。
- 正常状态：`#1F745D`；预警状态：`#A66A16`；冻结/风险：`#B84B46`。
- 边框：`#DCE3EA`；后台容器圆角以 3-5px 为主；阴影只用于抽屉层级和设备预览。
- 后台页面不使用渐变装饰、大圆角卡片、悬浮数据卡堆叠或营销页式大标题。

组件必须覆盖以下状态：

- 按钮：默认、按下、loading、禁用、风险确认。
- 表单字段：默认、聚焦、已填、字段错误、禁用、只读。
- 状态标签：正常、信息、预警、风险、禁用。
- 抽屉：打开、提交中、失败保留输入、成功关闭。
- 表格：加载、空、筛选无结果、错误、分页。
- 空态：首次空、筛选无结果、权限不可用、冻结只读。

## 响应式与长内容规则

小程序端以 390px 画板为基准，但实现必须验证 320px、375px、390px、430px 四个宽度。后台端必须验证 1280px、1440px 和宽表格场景。

长内容处理：

- 门店名、服务名、会员卡名最多展示两行，超过两行截断，并在详情页或展开态显示完整内容。
- 地址和营业时间允许换行，不压缩到不可读。
- 服务范围允许换行；达到 6 项时不应挤压主操作。
- 员工名、登录账号和状态同时出现时，状态可换到第二行，复制/修改操作仍需保持 44px 触控区域。
- 后台表格长文本可以截断，但必须能通过详情或悬停查看完整内容。

## 首屏优先级

| 页面 | 首屏主任务 | 次任务上限 | 后移内容 |
| --- | --- | --- | --- |
| O-START | 完成三项必填并创建门店 | 3 个必填项 | 创建后由工作台承接的运营配置。 |
| O-DASHBOARD 创建后待办 | 推进开放预约前下一步 | 创建员工、设置服务、创建会员卡 | 经营摘要、完整报表。 |
| O-DASHBOARD 运营态 | 今天先处理哪些会员权益和核销 | 待到店、待核销、低余额/到期预警 | 趋势、长期配置、完整排期分析。 |
| O-REPORT | 看清线下售卡、到店、核销和会员卡提醒 | 售卡明细、核销明细、预警处理 | 预约趋势、员工维度和深层分析。 |
| O-SCHEDULE-HOME | 找到待发布或异常时段 | 日期、复制、预检异常 | 历史排期分析。 |
| O-MEMBER-HOME | 添加会员并处理会员卡权益 | 待绑定、余额不足、即将到期 | 全量会员运营分析。 |
| M-CARDS / M-HOME | 确认绑定门店、卡包余额和最近核销 | 预约入口、服务记录、门店资料 | 完整自助约课筛选。 |
| S-TODAY / S-ROSTER | 完成今日到店确认和核销 | 卡异常提醒、核销阻断、服务记录 | 员工资料和长期记录。 |
| A-TENANTS / A-TENANT-DETAIL | 搜索租户并观察试点活跃度 | 发卡数、核销数、预警数、续期状态 | 复杂运营统计。 |

每个核心页面首屏最多保留 1 个主任务和 3 个次任务。若同屏信息超过该上限，应后移到详情、报表明细或下方分组。

## 空态与反馈规则

核心空态必须包含：

1. 为什么为空。
2. 系统已经知道什么。
3. 推荐主操作。
4. 替代路径。
5. 完成后页面会发生什么变化。

必须覆盖的空态包括：无员工、无服务、无会员、无会员卡、无排期、报表无数据、今日无服务、无可用卡、无预约记录、租户列表无结果和操作记录无结果。

`A-TENANTS` 为查询型数据表例外：租户列表无结果时仅在表格内容区显示“暂无数据”，不追加引导说明或“查看全部租户”按钮；总数为 0 时隐藏分页。其他业务流程型空态仍遵循上述五项结构。

试点楔子补充空态与预警态：

- 无发卡记录：说明还没有会员权益进入系统，主操作为添加会员并发卡，替代路径为先创建会员卡。
- 无待核销：说明今日没有已到店未核销会员，替代路径为查看全部核销记录或返回工作台。
- 无低余额/到期预警：说明当前没有需要跟进的会员卡，替代路径为查看全部会员卡。
- 预警已处理：说明已联系、已续卡或暂不处理，并保留处理时间和操作人。

四端操作反馈必须覆盖：loading、成功、字段错误、表单错误、页面级阻断、部分成功和禁用态。失败时必须保留输入，并把错误显示在字段旁和表单顶部摘要中；toast 只能作为补充。保存、发布、确认预约、取消预约、到店、核销、冻结、解冻和平台配置修改成功后，必须刷新来源页、列表或进入结果态。

## 可访问性规则

- 所有可点击区域不小于 44px。
- 状态必须用文字和颜色共同表达。
- 表单必须有可见 label，不得只用 placeholder。
- 后台按钮、筛选、分页、右侧抽屉和表格行操作必须支持键盘访问。
- 焦点态必须可见。
- 字段错误必须能关联到字段。
- 弹层打开后焦点进入弹层，关闭后回到触发元素。
- 动效必须支持减少动态效果降级。
