# Security

当前安全依据来自 MVP 产品规格和完整工程映射。阶段一统一治理认证、租户隔离、初始管理员、安全配置和关键写操作防重。

## 当前依据

- 产品规格：`product-specs/versions/mvp/spec.md`
- 实现说明：`product-specs/versions/mvp/implementation-notes.md`
- 工程入口：`architecture/index.md`

MVP 必须保持多租户数据隔离、角色权限校验和冻结租户访问限制。当前不接入线上支付、微信授权手机号或文件上传。

## 实施基线

- 四端统一使用数据库支持的不透明 Bearer 会话，数据库只保存 token 哈希。
- 业务端 `tenant_id` 只从认证上下文注入，客户端传入值不可信。
- 平台后台跨租户访问仅允许显式后台查询，不复用业务端租户上下文。
- 首个管理员只允许通过显式环境变量一次性引导，不提供默认账号或密码。
- 员工登录只校验 PBKDF2 哈希；店长按员工查看的可恢复凭据使用独立 AES-256-GCM 密文表和版本化部署密钥保存。员工列表不得批量下发密码，逐条查看必须校验租户、限频、记录无密码审计并禁止响应缓存。
- 微信 AppSecret、数据库密码和试点域名配置不得提交到仓库。
- 发卡、预约、取消、到店、核销、冻结和配置修改要求幂等保护与审计。

上述阶段一基线已落入代码和 V1；本地测试替身仅在 `local`/`test` profile 注册。仓库不含默认管理员账号、默认管理员密码、数据库密码、员工凭据加密密钥或微信密钥，真实值只允许从部署环境注入。
