# 闲遇 MVP Prototype Notes

版本：MVP
文档日期：2026-06-08
当前 UI 设计稿：`../../../design-docs/versions/mvp/prototype.html`

## 原型说明

MVP 原型是闲遇独立正式版本包的一部分，按开发可对照设计稿组织。原型覆盖通用约课模型、页面 ID、核心字段、主操作、异常态、冻结态和报表。

MVP UI 设计稿必须延续既有视觉风格和组件语言，同时按 MVP 页面契约重新组织主体内容。所有画面都应对应 MVP 的服务项目、资源、员工、会员卡售价、排期、预约、核销和报表，并覆盖门店资料自定义填写和关系端门店资料展示。全部端的画板均会标记页面类型：“效果呈现”代表用户实际会看到或操作的页面/状态，“研发说明”代表仅供研发实现时参考的规范说明画板；当前只有 O-FEEDBACK 四端操作反馈规范为研发说明，教练端、会员端和平台后台 WEB 端页面均为效果呈现。

## 试点楔子重排要求

当前完整 MVP 原型继续保留全量页面覆盖。根据 `pilot-wedge.md`，第一阶段原型重排应优先呈现“发卡 -> 到店 -> 核销 -> 余额变化 -> 低余额 / 到期预警 -> 续卡跟进”的权益经营主线。

后续修改 `../../../design-docs/versions/mvp/prototype.html` 时必须满足：

- 链路地图新增或前置“试点楔子”链路，覆盖发卡、到店、核销和预警；完整预约链路作为第二阶段能力保留。
- 店长工作台运营态优先展示待到店、待核销、低余额、即将到期、已过期和本月线下售卡摘要。
- 会员首页优先展示添加会员并发卡、待绑定、低余额和即将到期会员；全量会员列表后移。
- 报表首页第一屏优先展示线下售卡、到店、核销和会员卡提醒；预约趋势、服务表现和员工维度后移。
- 员工端今日服务和预约名单优先服务到店确认与核销确认；员工资料和服务记录不得压过核销路径。
- 会员端卡包或首页优先展示绑定门店、会员卡余额和最近核销记录；约课入口保留但不作为第一阶段首屏主任务。
- 平台后台租户详情补充试点观测摘要，包括发卡数、核销数、预警数和客服续期状态。

## 覆盖画面

- 链路地图：店长启用、会员预约、员工履约、报表预警、试用冻结。
- 店长端：微信登录、开始使用新用户告示、开始使用、门店资料、营业时间、资源管理新增资源底部抽屉态、资源管理列表态、资源删除确认/阻断态、工作台创建后待办态、员工列表、员工页内新增员工底部抽屉状态、员工页内修改员工底部抽屉状态、服务项目、服务项目资源员工下拉多选状态、服务无员工阻断态、会员卡模板入口、会员卡模板次数卡、会员卡模板期限卡、添加会员并发卡、发卡成功邀请码状态、发布预约时段、排期预检失败态、排期发布成功态、工作台运营态、排期首页、会员首页、报表、报表明细、我的、冻结页和四端操作反馈规范；门店资料页必须展示经营项目和服务标签自定义填写指导，不展示营业时间补齐步骤或完整预览；营业时间页只展示营业时间配置和轻量提示，不展示完整门店资料预览；完整门店展示预览放在 O-START 必填项完成状态，且必须包含营业时间；开始使用新用户告示必须说明免费使用权益和当前试用天数并提供我知道了确认，当前默认值为 30 天，由平台配置决定；首次开店流程采用 O-START 清单式引导，门店资料、营业时间和履约资源为必填项，创建门店按钮默认禁用，三个必填项完成后变为可点击并创建门店后进入工作台；工作台负责“今天要处理什么、下一步要做什么、哪些异常要关注”，创建后待办态展示开放预约前配置进度和下一步待办，不展示无价值的三项 0 指标；运营态展示今日处理、任务化动作、风险提醒和轻量经营摘要，O-REPORT 首页保留销售额、预约、到店、核销、售卡明细、预约到店、服务表现和会员卡提醒等业务内容，并用店长可理解的分组、文案和趋势图提升可读性；报表明细下钻只在 O-REPORT-DETAIL 内通过标签、筛选和列表切换维度，不新增独立会员、会员卡、服务或员工详情页；员工列表不展示待完善状态统计，仅员工列表行支持复制员工姓名和登录账号；员工列表页不展示“修改员工账号”和“新增员工”说明卡片；新增员工抽屉和修改员工抽屉均不提供复制账号操作，修改抽屉展示账号资料修改、密码修改、启用/停用、物理删除账号和删除前关联项目校验；店长端所有需要店长输入或配置的表单字段必须使用红色“必填”标记；服务项目必须按真实店长创建场景展示基础信息、启用前检查、资源与员工下拉多选，资源和员工均支持多选且停用项不可选；服务无员工时仅可保存草稿；会员卡模板不展示组合卡，入口页只进入次数卡和期限卡；发卡成功页只展示邀请码、绑定提醒、重新生成、实收金额和绑定状态等用户能理解的信息，不暴露后台枚举；排期预检失败态逐项展示失败原因并禁用发布；排期保存草稿和发布成功后返回排期首页对应日期并高亮新时段；O-STORE、O-HOURS、O-RESOURCE 首次开店保存成功后返回 O-START；资源管理列表态位于新增态之后，用于保存资源后的确认和返回清单；资源行必须将启用/停用作为只读状态标识，并提供修改、删除入口；资源删除必须二次确认，有关联未来排期、服务项目占用或会导致启用资源少于 1 个时禁用确认；新增资源抽屉、新增员工抽屉和修改员工抽屉底部操作随表单滚动出现在内容底部，不固定悬浮；店长端底部导航统一为工作台、排期、会员、报表、我的；冻结后店长端强制进入冻结页，除 O-FROZEN 外不允许访问其他业务页面或设置页面。
- `O-LOGIN` 视觉规则：页面场景背景必须延伸至状态栏，品牌导航行必须按微信胶囊位置安全避让，不得叠加独立白色状态栏占位；品牌统一显示“闲遇-店长端”，不在右侧重复展示角色；页面固定为一屏并禁用无内容拖动，矮屏下必须保持登录按钮和底部说明完整可见。
- 教练端：独立于会员端展示，账号密码登录沿用既有登录页；覆盖账号状态、首次完善资料、今日服务、今日无服务空态、预约名单、到店确认成功、核销确认、核销阻断、服务记录、我的和冻结提示。登录后关键页面必须展示归属门店资料摘要，摘要包含营业时间。
- 会员端：独立于教练端展示，微信登录沿用既有登录页；覆盖邀请码填写、加载门店信息、核对门店并确认绑定、绑定失败、卡包、约课首页、服务详情、确认预约、无可用卡、预约成功、候补成功、我的预约、预约详情、取消预约、取消阻断、服务记录、我的和冻结提示。邀请码绑定必须呈现“填写邀请码 → 查询/加载门店信息 → 核对门店与会员卡 → 确认绑定”的分步状态，查询门店信息不直接完成绑定；绑定前和绑定后必须展示门店资料摘要，摘要包含营业时间；预约详情必须承接待服务、候补、已完成和已取消状态，超过取消截止或租户冻结时进入取消阻断态。
- 平台后台 WEB 端：登录页和登录后的全部页面采用“企业经纬”企业运营工作台风格，覆盖租户管理列表、租户详情右侧抽屉、租户调整右侧抽屉、客服微信配置、平台配置与右侧抽屉编辑态、操作记录。登录页只呈现平台说明、账号、密码、登录按钮和必要错误提示，不展示注册入口、内部账号说明或装饰性边角线；登录后使用深海军蓝侧栏、冷灰白工作区、商务蓝主操作、紧凑表格和右侧抽屉，并采用“侧栏导航 + 单一内容头部”，不重复展示顶部面包屑栏。租户由店长首次微信登录自动开通，后台不得提供新建租户入口，也不得提供支付、收款、退款、文件上传、二维码上传或图片上传；租户管理列表的五项状态概览使用统一底色和层级，不使用顶部状态彩线，并保留首列固定、客服微信长文本截断、线下售卡金额展示和左对齐详情/调整按钮；租户调整中未冻结状态展示冻结账户操作，冻结状态仅展示延期并解冻，不提供独立解冻账户卡片；客服微信配置使用与其他后台页面相同起始线的单一全宽表单，不展示冻结页预览或三端展示规则，展示文案与展示范围默认使用单行输入高度并最多自适应到三行；平台配置使用可编辑下拉筛选、右侧查询按钮和右侧抽屉编辑，标题区不重复展示后续生效提示，修改必填项用红色标记；操作记录时间展示为 `YYYY-MM-DD HH:mm:ss`。

## 视觉说明

- 视觉风格：小程序采用健康可信的高密度业务工具风格；平台后台采用克制、商务、可扫读的“企业经纬”运营工作台风格。
- 画板和组件：使用 390px 小程序画板、桌面后台画板、登录插画、业务卡片、状态条、底部导航、后台侧栏和表格组件。
- 小程序主色：松绿色 `#2F7D6E`；深色 `#17211B`；风险/阻断 `#E86F4E`；数据信息 `#3F6E9D`；预警/试用 `#B98532`；背景 `#F5F7F2`；业务卡片圆角以 8px 为主。
- 平台后台导航底色：`#172433`；活动面 `#213246`；主操作 `#285F98`；强调主操作 `#194978`；工作区背景 `#F2F5F8`；标题文本 `#172233`；边框 `#DCE3EA`；容器圆角以 3-5px 为主。
- 平台后台不使用渐变装饰、大圆角卡片、悬浮数据卡堆叠、开发说明式标签或营销页式大标题。
- 不使用图片上传、头像上传或二维码上传；头像使用系统生成文字占位。

## 设计系统执行规则

MVP 实现不得只按单个画板临摹，应按统一组件语言实现。当前设计系统入口为 `../../../DESIGN.md`，本版本包内按以下规则约束实现。

### 组件状态矩阵

| 组件 | 必须覆盖的状态 |
| --- | --- |
| 主按钮 | 默认、按下、loading、禁用、风险确认。 |
| 次按钮 | 默认、按下、禁用。 |
| 状态标签 | 正常、信息、预警、风险、禁用，且必须有文字。 |
| 表单字段 | 默认、聚焦、已填、字段错误、禁用、只读。 |
| 列表行 | 默认、选中、不可选、处理中。 |
| 抽屉 | 打开、提交中、失败保留输入、成功关闭。 |
| 表格 | 加载、空、筛选无结果、错误、分页。 |
| 空态 | 首次空、筛选无结果、权限不可用、冻结只读。 |

### 首屏优先级

核心页面首屏最多保留 1 个主任务和 3 个次任务。

| 页面 | 主任务 | 次任务 |
| --- | --- | --- |
| O-START | 完成三项必填并创建门店 | 门店资料、营业时间、履约资源。 |
| O-DASHBOARD 创建后待办 | 推进开放预约前下一步 | 创建员工、设置服务、创建会员卡。 |
| O-DASHBOARD 运营态 | 今天先处理哪些会员权益和核销 | 待到店、待核销、低余额/到期预警。 |
| O-REPORT | 看清线下售卡、到店、核销和会员卡提醒 | 售卡明细、核销明细、预警处理。 |
| O-SCHEDULE-HOME | 找到待发布或异常时段 | 日期、复制、预检异常。 |
| O-MEMBER-HOME | 添加会员并处理会员卡权益 | 待绑定、余额不足、即将到期。 |
| M-CARDS / M-HOME | 确认门店、卡包余额和最近核销 | 预约入口、服务记录、门店资料。 |
| S-TODAY / S-ROSTER | 完成今日到店确认和核销 | 卡异常提醒、核销阻断、服务记录。 |
| A-TENANTS / A-TENANT-DETAIL | 找到租户并观察试点活跃度 | 搜索、状态筛选、发卡/核销/预警摘要。 |

### 空态结构

核心空态不得只写“暂无数据”。必须说明：

1. 为什么为空。
2. 系统已经知道什么。
3. 推荐主操作。
4. 替代路径。
5. 完成后页面会发生什么变化。

必须覆盖：无员工、无服务、无会员、无会员卡、无排期、报表无数据、今日无服务、无可用卡、无预约记录、租户列表无结果和操作记录无结果。

`A-TENANTS` 为查询型数据表例外：租户列表无结果时仅在表格内容区显示“暂无数据”，不追加引导说明或“查看全部租户”按钮；总数为 0 时隐藏分页。其他业务流程型空态仍遵循上述五项结构。

试点楔子补充空态：

- 无发卡记录：说明还没有会员权益进入系统，推荐添加会员并发卡，替代路径为先创建会员卡模板。
- 无待核销：说明今日没有已到店未核销会员，推荐查看全部核销记录或返回工作台。
- 无低余额/到期预警：说明当前没有需要跟进的会员卡，推荐查看全部会员卡。
- 无试点活跃数据：后台租户详情说明该租户尚未发卡或核销，推荐联系店长完成首张发卡。

### 表单反馈

保存、发布、创建员工、创建服务、创建会员卡、发卡、发布排期、确认预约、确认核销、取消预约、冻结租户、调整期限、解冻和修改平台配置必须覆盖：

- loading：按钮显示处理中并禁用重复提交。
- 成功：展示明确成功文案，并返回来源页、刷新列表或进入结果页。
- 字段错误：错误显示在字段旁，表单顶部展示错误摘要。
- 表单错误：保留输入，说明失败原因和下一步。
- 部分成功：说明已保存项和待处理项。
- 禁用：说明不可操作原因，例如缺员工、无适用卡、冻结。

试点楔子补充状态：

- 发卡成功但会员未绑定：结果页展示会员、卡名、实收金额、邀请码、有效期和下一步转交动作。
- 到店已确认但未核销：员工端必须展示继续核销入口，并说明未核销不会扣减会员卡。
- 核销成功：展示扣前余额、本次扣减、扣后余额、操作员工和会员端可见记录；若触发低余额，应在同一结果页提示。
- 预警处理：低余额和到期预警支持待处理、已联系、已续卡、暂不处理等可理解状态，状态必须有文字。

### 响应式与可访问性

- 小程序端必须验证 320px、375px、390px、430px 宽度。
- 后台端必须验证 1280px、1440px 和宽表格场景。
- 长门店名、长服务名、长会员卡名最多展示两行，超过两行截断并提供完整查看路径。
- 服务标签允许换行，不得压缩到不可读。
- 后台表格长文本可截断，但必须能通过详情或悬停查看完整内容。
- 所有可点击区域不小于 44px；并排按钮间距不小于 8px。
- 表单必须有可见 label，不得只用 placeholder。
- 后台端按钮、筛选、分页、右侧抽屉和行操作必须支持键盘访问。
- 焦点态必须可见；字段错误必须能关联到字段。
- 状态不得只靠颜色表达，必须有文字或图标说明。

## 读取规则

## 页面 ID 说明

- 店长端使用 `O-*`。
- 员工端使用 `S-*`。
- 会员端使用 `M-*`。
- 平台后台使用 `A-*`。
- 报表页面 `O-REPORT` 和 `O-REPORT-DETAIL` 是 MVP 新增重点页面。
