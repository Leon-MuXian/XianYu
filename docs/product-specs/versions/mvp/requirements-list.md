# 闲遇 MVP 需求清单

版本：MVP  
文档日期：2026-05-30

## 1. 产品边界

| 编号 | 需求 | 优先级 | 验收口径 |
| --- | --- | --- | --- |
| R-001 | 产品必须支持多业态预约制门店，不把课程、教练、教室写死为单一行业 | P0 | 文档、页面和字段使用服务项目、员工、资源等通用模型 |
| R-002 | 保留会员卡权益体系 | P0 | 支持次数、有效期、适用服务、核销规则、会员持卡 |
| R-003 | 不接入微信授权手机号 | P0 | 店长和会员只使用微信 openid 登录；无手机号授权按钮 |
| R-004 | 不做线上支付 | P0 | 无支付、购买、订单、退款、发票、分账入口 |
| R-005 | 不做任何文件上传 | P0 | 无上传头像、图片、二维码、附件、资质文件入口 |
| R-006 | 平台营收只支持试用 + 添加客服微信人工续期 | P0 | 冻结页展示客服微信；后台人工延长期限 |

## 2. 店长小程序

| 编号 | 需求 | 优先级 | 验收口径 |
| --- | --- | --- | --- |
| O-001 | 店长微信一键登录 | P0 | 登录成功后按门店和冻结状态分流 |
| O-002 | 首次开始使用页 | P0 | 首次登录且无门店的新用户，进入开始使用前必须展示免费试用告示和当前试用天数；当前默认试用天数为 30 天，由平台配置决定；确认后展示固定首屏的开店清单，仅保留门店资料、营业时间、履约资源三个可操作必填项，不展示无法在本页操作的后续配置；员工、服务、会员卡、会员、排期可在创建后补充；创建门店按钮默认禁用，三个必填项完成后变为可点击；完成态由顶部状态和三条清单承载，不重复展示门店预览或二次确认卡 |
| O-003 | 门店建档 | P0 | 门店名称在全平台已创建门店中唯一，草稿不占用名称；包含店长自填的 1 到 6 个服务范围短标签、城市、区/县、详细地址和自由文本联系电话；行政区划由后端数据库初始化并通过接口获取，地址使用底部抽屉依次选择城市、区/县并填写详细地址，城市、区/县和详细地址均为必填且分别显示红色“必填”标记，抽屉内不展示合成地址；联系电话不做格式或重复校验；其他页面必填项同样使用红色“必填”标记，不展示开店进度、已填数量、页面说明卡、营业时间或完整门店展示预览；首次开店期间主操作为保存并返回清单 |
| O-004 | 营业时间设置 | P0 | 支持在周一至周日的统一选择区设置营业/休息，所有已选日期逐日设置开始结束时间，不展示独立周末设置；不展示开店必填、已营业、可预约三个统计卡片；首次开店期间主操作为保存并返回清单，不展示完整门店资料预览 |
| O-005 | 资源管理 | P0 | 支持新增、修改、删除、停用、排序、容量，首次引导可从开店清单进入新增资源底部抽屉态，保存资源后回到资源列表态；列表态资源行将启用/停用作为只读状态标识，并提供修改和删除入口，底部主操作为完成并返回清单，排序通过新增/修改资源表单维护；新增资源底部抽屉包含资源名称、资源类型、默认容量、排序和启用状态，资源类型固定项为房间、场地、床位、设备、工位；选择“自定义”后必须填写真实类型，保存时真实类型直接写入 `resourceType`，编辑非固定类型资源时自动回显为自定义模式；至少 1 个启用资源；删除资源必须进入二次确认态，展示影响范围和阻断原因，有未来排期或导致启用资源少于 1 个时禁用确认 |
| O-006 | 创建员工账号 | P0 | 在员工页右上角点击新增员工后使用底部抽屉创建账号，包含姓名、角色标签、登录账号、初始密码、确认密码；登录账号按 Unicode NFKC、去除首尾空白和小写转换后必须全平台唯一，重复创建必须保留表单并在登录账号字段提示更换；初始密码至少 8 位且必须与确认密码一致；创建成功或取消后回到员工列表；新增员工抽屉不提供复制账号操作 |
| O-007 | 员工账号修改 | P0 | 员工账号由店长统一管理；员工列表行支持一键复制员工姓名、登录账号和当前登录密码，查看或编辑员工时直接回显账号全部信息，不要求先重置密码；密码哈希继续用于员工登录校验，可恢复凭据以独立 AES-256-GCM 密文保存，员工列表不批量下发密码，仅在店长复制或打开编辑时按员工读取；抽屉支持账号资料修改、密码修改、启用、停用、物理删除账号，不提供重复的独立复制卡片；登录账号修改仍须满足全平台唯一，保留自身原账号不视为重复；停用账号继续占用登录账号，物理删除后才释放；历史仅有密码哈希且没有加密凭据的账号无法恢复原密码，只需一次性设置新密码，之后即可直接查看和复制；删除账号前必须校验关联服务项目、会员卡适用范围、未来排期等项目，有关联时禁用删除并提示先解除关联，操作完成后关闭抽屉并刷新列表状态 |
| O-008 | 服务项目管理 | P0 | 默认进入“服务与排期”列表，展示资源数、员工数和时长并支持全部/可排期/待处理筛选；服务名称区保持中性并在容量说明下方用色点和文字展示状态，资源、员工、时长数据区分别使用绿色、暖黄色、灰色轻底色区分启用、草稿、停用，列表行不显示胶囊状态标签或启停操作；新增和修改均在列表页打开底部抽屉，表单按会员可见信息、预约参数、履约范围分组，不展示服务状态卡或解释卡；修改抽屉右上角更多菜单始终提供可点击的删除服务操作，启用项目点击后提示先停用，草稿或停用项目点击后进入二次确认；会员卡或任意排期仍有关联时禁止删除，无业务关联的草稿或停用项目物理删除后释放租户内名称；适用资源和可履约员工均使用下拉多选，超过 2 项时只显示已选数量，停用资源和停用员工不可选；规范化名称在同租户内唯一、不同租户可同名，冲突返回 `SERVICE_NAME_TAKEN` 并在名称字段提示；无可履约员工时仅允许保存草稿，启用和排期发布禁用 |
| O-009 | 会员卡管理 | P0 | 默认进入“会员卡管理”列表，展示会员卡总数、次数卡数和期限卡数，支持全部/次数卡/期限卡筛选；页面只保留一个新增按钮，点击后选择次数卡或期限卡，再进入现有新增会员卡页面，填写页不再提供卡类型切换；点击已有会员卡进入修改页面；次数卡包含卡名、售价、总次数、有效期、低余额提醒、适用服务、适用员工，期限卡包含卡名、售价、有效期、适用服务、适用员工，店长端不展示由平台后台统一配置的到期提醒；新增和修改页面不展示“发给会员后怎么用”或“保存前检查”说明块；服务和员工多选超过 2 项时只显示已选数量；规范化名称在同租户内唯一、不同租户可同名，冲突返回 `CARD_TEMPLATE_NAME_TAKEN` 并在名称字段提示；售价支持 0 和两位小数且不能为负数；修改页常驻展示删除入口，启用模板先停用，停用且从未发卡的模板二次确认后物理删除，已发卡模板返回 `CARD_TEMPLATE_IN_USE` 并保留停用状态和全部历史权益 |
| O-010 | 添加会员并发卡 | P0 | 录入会员姓名和必填联系方式，选择会员卡、确认门店线下实收金额后生成邀请码并发放会员卡；会员编号由后台生成且全平台唯一，页面不提供会员编号输入；添加页不展示“实收确认”或“保存后生成邀请码”提示卡；发卡成功态只展示店长能理解的邀请码、有效期、复制/转交、绑定状态、重新生成和实收金额，不暴露后台枚举值 |
| O-011 | 排期发布 | P0 | 排期首页统一展示日期、已发布和草稿时段，新增和草稿续编均在当前页底部抽屉完成，不跳转独立发布页；明日及更之后的日期支持一键复制昨日排期，复制结果保存为草稿并跳转目标日期供店长检查后发布，目标日期已有相同时段时跳过且不得重复创建；店长选择服务、员工、资源、日期和开始时间，时段容量自动采用所选履约资源容量，结束时间由服务端按服务时长生成；服务选择后只能使用其绑定的启用员工和资源，时段占用项需明确标记且不可选；提交发布时由服务端检查未来时间、营业时间、绑定关系、员工/资源重叠和同时覆盖服务与员工的启用会员卡，失败通过提交提示反馈原因，不在抽屉内展示完整检查清单，但完整选择仍可保存草稿；发布时服务端必须再次预检，数据库阻断同租户已发布时段的员工或资源重叠；保存或发布成功后关闭抽屉、保留对应日期、刷新并高亮新时段，页面与抽屉滚动条均不显示 |
| O-012 | 工作台 | P0 | 创建后待办态展示开放预约前配置进度和下一步待办；“发布预约时段”只以服务、员工、资源和会员卡适用范围形成完整可预约组合为硬前置，不以是否已有会员作为发布前置；存在配置缺口时跳转首个缺口，存在未来草稿时进入对应日期并打开草稿抽屉，配置完整且无草稿时进入排期页自动打开新增抽屉；已有未结束的已发布时段（进行中或未来）后移除“发布预约时段”首个预约待办；运营态展示今日预约总量、待履约、已完成，只有存在会员卡提醒或排期草稿时才展示店长跟进区域；员工端负责到店确认和权益处理，店长端不重复执行；任务动作聚焦查看履约进度、跟进低余额、临期会员和处理排期草稿，不重复底部导航文案，不承载完整报表 |
| O-013 | 报表首页 | P0 | 报表首页面向店长优先呈现销售额、预约、到店、核销四个结果；支持本月、上月、选月份、全部范围；售卡明细、预约到店、服务表现、会员卡提醒以店长可理解的入口呈现，低余额、到期和已过期进入“今天先处理” |
| O-014 | 报表明细 | P1 | 从销售额、预约到店、服务表现、会员卡提醒进入对应明细；售卡明细展示会员、卡名、实收金额、售卡日期，预约/到店/核销明细展示会员、服务、员工和状态；MVP 下钻只在报表明细页内用标签、筛选和列表切换维度，不新增独立会员、会员卡、服务或员工详情页 |
| O-015 | 我的页 | P0 | 提供门店账号、使用状态、门店设置和运营配置入口；不承担主要待办推进 |
| O-016 | 冻结页 | P0 | 租户冻结后店长端强制进入 O-FROZEN，仅展示原因、影响范围、客服微信和门店摘要；除 O-FROZEN 外不允许访问工作台、我的、员工、服务、会员卡、会员、排期、报表等页面 |
| O-017 | 四端操作反馈规范 | P0 | 店长、员工、会员和平台后台的保存、发布、创建员工、发卡、重发邀请码、确认预约、取消预约、到店、核销、冻结、延期并解冻、平台配置修改等操作必须有 loading、成功、失败、字段错误、页面级阻断和禁用原因；失败时保留输入并说明原因，成功后刷新来源页、列表或进入结果态 |

## 5. 平台后台

| 编号 | 需求 | 优先级 | 验收口径 |
| --- | --- | --- | --- |
| A-001 | 后台账号密码登录 | P0 | 不提供注册入口 |
| A-002 | 租户列表 | P0 | 展示由店长首次微信登录自动开通的租户；支持试用中、即将到期、已冻结、已延长状态展示，支持搜索、状态筛选、到期筛选、分页，并以按钮组呈现详情、冻结账户、延期并解冻等行操作；不得提供后台新建租户入口 |
| A-003 | 租户详情 | P0 | 展示租户状态、门店资料、业务摘要和冻结对店长/教练/会员端的影响；冻结租户必须进入二次确认态，填写冻结原因、展示三端影响并勾选确认后才允许提交，成功后刷新租户详情状态 |
