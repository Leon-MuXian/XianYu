# PDR-0004 店长管理员工登录凭据

状态：accepted
日期：2026-07-25
关联版本：mvp

## 背景

员工不提供自助注册，员工账号由店长创建、维护并交付。店长需要在员工列表直接复制完整登录信息，也需要在查看或编辑员工账号时看到当前账号和密码。仅在创建页面短暂保留密码会使日常交付频繁退化为重置密码，增加操作成本并打断员工登录。

## 决策

- 店长可以按员工逐条查看当前登录账号和密码，并直接复制姓名、登录账号和登录密码。
- 员工登录继续只校验 PBKDF2 密码哈希；可恢复凭据独立保存在 `staff_credential_secret`，不以明文写入数据库。
- 可恢复凭据使用 AES-256-GCM 加密、随机 nonce，并以稳定的 `tenant_id + staff_account_id` 作为附加认证数据；每行记录密钥版本，以支持密钥轮换。
- 员工列表只返回凭据是否可用，不批量返回密码。查看或复制时调用单员工凭据接口；接口执行租户归属校验、限频和无密码审计，并返回 `no-store` 响应。
- 创建员工和重置密码必须在同一事务中同步写入密码哈希与加密凭据。创建、重置的幂等响应、审计和日志不得包含密码。
- 只有历史上仅保存密码哈希且尚无加密凭据的员工无法恢复原密码；此类账号需要店长一次性设置新密码，之后即可直接查看和复制。

## 影响

- 该能力允许店长在不重置员工密码的情况下获得员工身份凭据。产品接受这一权限，因为员工账号属于门店统一创建和管理的数据；平台仍通过单条读取、租户隔离、限频和审计降低滥用风险。
- 凭据加密密钥必须由部署环境提供，禁止提交默认密钥或启动时临时生成。密钥丢失会导致可恢复凭据不可解密，但不影响现有密码哈希校验登录。
- 密钥轮换必须同时保留旧密钥读取能力，待旧版本密文全部重加密后才能移除旧密钥。
